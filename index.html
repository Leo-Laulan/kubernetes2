Linux & Conteneurs Bas Niveau Fondamental
  • Namespaces (Isolation) :
    • UTS : nodename / hostname indépendant.
    • PID : PID 1 propre à chaque conteneur.
    • Mount : vue hiérarchique racine isolée.
    • IPC : mémoire partagée et sémaphores isolés.
  • Cgroups : Limitation matérielle stricte (CPU, RAM, I/O disque, bande passante réseau).
  • Sécurité : SELinux (Mandatory Access Control) + Seccomp (filtre et bloque les appels système risqués).
  • Podman vs Docker : Podman est daemonless (pas de processus centralisé `dockerd`), exécute directement via runC et supporte le mode rootless.
Architecture du Control Plane Cœur K8s
  • etcd : Magasin clé-valeur distribué, unique source de vérité. Algorithme de consensus RAFT (Leader, Follower, Candidat).
  • API Server (kube-apiserver) : Point central d'accès REST (CRUD). Seul composant à communiquer avec etcd. Pipeline : Authentification ➔ Autorisation ➔ Contrôle d'admission.
  • Scheduler : Associe les pods « non liés » aux worker nodes selon les ressources demandées, affinités et contraintes.
  • Controller Manager : Boucle infinie de réconciliation : compare en continu l'état réel à l'état désiré et émet des ordres à l'API Server.
  • Kubelet : Tourne sur chaque Worker Node, reçoit les instructions de l'API Server et pilote le runtime (CRI / runC).
Pods & ReplicaSets (TP1) Pièges Examen
  • Cycle de vie du Pod :
    • Pending : pod accepté mais image en cours de pull ou en attente d'assignation nœud.
    • Running : assigné à un nœud et au moins un conteneur tourne.
    • Succeeded / Failed : terminé avec code 0 ou erreur/kill.
  • Éphémérité : Un pod mort n'est jamais re-ordonnancé avec le même UID. Il est remplacé par un nouveau pod doté d'un UID neuf.
  • ReplicaSet & Sélecteurs : Le RS compte les pods UNIQUEMENT par leurs labels (`matchLabels`). Si un pod tiers a le même label, le RS détecte un surplus et tue un pod !
Deployments & Stratégies (TP1) TP1 Majeur
  • Deployment : Pilote déclarativement les ReplicaSets pour gérer l'historique et les révisions.
  • RollingUpdate (défaut) : Remplacement progressif sans rupture de service.
    • maxSurge (défaut 25%) : pods tolérés au-dessus du quota.
    • maxUnavailable (défaut 25%) : pods tolérés indisponibles.
  • Recreate : Tue brutalement l'ensemble des anciens pods avant de lancer les nouveaux (coupure de service).
  • Blue/Green : 2 environnements complets en parallèle. Bascule instantanée du trafic mais double le coût matériel.
  • Canary : Route un pourcentage minime d'utilisateurs réels sur la nouvelle version avant d'étendre le déploiement.
Services Réseau (TP2) Concepts Clés
  • Les 3 Ports d'un Service :
    • port : port d'écoute interne du service.
    • targetPort : port cible sur le conteneur du Pod.
    • nodePort : port externe ouvert sur TOUS les nœuds (plage 30000-32767).
  • ClusterIP (Défaut) : IP virtuelle interne au cluster. Inaccessible de l'extérieur. Indispensable pour sécuriser le backend (Redis).
  • Endpoints : Objet auto-généré listant les adresses IP réelles des pods correspondant aux labels du sélecteur.
Gateway API & HTTPRoute (TP2) Focus TP2
  • Architecture par Rôles :
    • GatewayClass (Infra/kgateway) ➔ Gateway (Admin/infra-gateway) ➔ HTTPRoute (Toi/ns-llaula).
  • Composants kgateway :
    • Control Plane : déploiement `kgateway` dans `kgateway-system`.
    • Data Plane : proxy Envoy déployé dans `infra-gateway`.
  • Diagnostic HTTPRoute :
    • `Accepted: True` : route acceptée par la Gateway parente.
    • `ResolvedRefs: False` (Reason: `BackendNotFound`) : le service pointé dans `backendRefs` est introuvable ➔ Envoy retourne une erreur 500/503.
