☸️ K8s Exam Prep R5A-09

🧠 Architecture Kubernetes Indispensable
  • Control Plane (Cerveau) :
    • etcd : Base clé-valeur distribuée (consensus RAFT), source unique de vérité.
    • API Server : Point d'entrée unique (REST CRUD), seul composant parlant à etcd.
    • Scheduler : Affecte les pods non liés à des nœuds selon ressources/affinités.
    • Controller Manager : Boucle de réconciliation (état actuel = état souhaité).
  • Worker Nodes (Exécution) :
    • Kubelet : Agent du nœud, communique avec l'API Server et le container runtime.
    • Kube-proxy : Gère les règles réseau et le routage des services.
📦 Conteneurs sous le capot Concept
  • Piliers Linux :
    • Namespaces : Isolation (PID, Mount, UTS=hostname, IPC).
    • Cgroups : Limitation et allocation des ressources (CPU, RAM, I/O).
    • SELinux / Seccomp : Sécurité et filtrage des appels système autorisés.
  • Docker vs Podman :
    • Docker s'appuie sur un démon centralisé (`dockerd`).
    • Podman est daemonless (sans démon), les conteneurs sont lancés directement par runC (compatible rootless).
  • Déclaratif vs Impératif : En déclaratif, on décrit l'état final souhaité dans un fichier YAML ; Kubernetes s'occupe de l'auto-réparation.
🔄 Pods & ReplicaSets TP1 Majeur
  • Cycle de vie du Pod :
    Pending (téléchargement image / non assigné) ➔ Running (au moins 1 conteneur tourne) ➔ Succeeded (fini avec code 0) ou Failed (erreur).
  • Nature du Pod : Entité éphémère dotée d'un UID unique. S'il meurt, il n'est pas ressuscité, mais remplacé avec un nouvel UID.
  • ReplicaSet : Garantit qu'un nombre précis de réplicas tourne en permanence. Il ne filtre que par labels (`matchLabels`). Si un pod tiers a le même label, le RS en tue un pour respecter la consigne !
🚀 Deployments & Mises à jour TP1 Majeur
  • Rôle : Objet de plus haut niveau gérant les ReplicaSets de façon déclarative (permet rollouts, rollbacks et révisions).
  • Stratégies natives :
    • RollingUpdate (Par défaut) : Remplacement progressif sans coupure. Réglé par maxSurge (dépassement autorisé) et maxUnavailable (indisponibles autorisés).
    • Recreate : Tue tous les anciens pods avant de lancer les nouveaux (provoque une coupure de service).
  • Stratégies avancées :
    • Blue/Green : Deux environnements identiques complets. Bascule instantanée du trafic mais coûte le double de ressources.
    • Canary : Achemine une petite fraction du trafic réel vers la nouvelle version pour tester la stabilité avant déploiement total.
🌐 Services Réseau K8s Concepts
  • Problème résolu : Les pods meurent et changent d'IP. Le service offre une IP stable et un nom DNS interne.
  • Types de Services :
    • ClusterIP (Défaut) : Uniquement accessible à l'intérieur du cluster (ex: Base de données Redis).
    • NodePort : Ouvre un port fixe sur chaque worker node (plage 30000-32767). Inconvénient : IP statique de nœud requise et ports limités.
    • LoadBalancer : Crée un équilibreur chez un fournisseur cloud externe (L4 ou L7).
🚪 Gateway API & HTTPRoute TP2 Focus
  • Modèle orienté rôles :
    • GatewayClass : Géré par le projet d'infrastructure (ex: `kgateway.dev/kgateway`).
    • Gateway : Géré par les admins (ex: `main-gateway` dans `infra-gateway`).
    • HTTPRoute : Géré par le développeur/étudiant dans son propre namespace.
  • Routage HTTP : Permet d'utiliser le port 80/443 standard et d'aiguiller le trafic selon le nom d'hôte (`hostnames`) vers un service frontend en ClusterIP.
  • Diagnostics de Route :
    • `Accepted: True` = Syntaxe et liaison à la Gateway acceptées.
    • `ResolvedRefs: False` (Reason: `BackendNotFound`) = Le service visé par la route n'existe pas (erreur 500/503 retournée par Envoy).
⚡ Commandes Vitales pour l'Évaluation
  • Initialisation obligatoire du lab : source labs-config.sh
  • Créer / Mettre à jour depuis un fichier : kubectl apply -f mon-fichier.yaml -n ns-login
  • Inspecter en détail / Événements d'un objet : kubectl describe <pod|rs|deploy|svc|httproute> <nom> -n ns-login
  • Modifier l'échelle (Scale UP / DOWN) : kubectl scale deployment <nom> --replicas=4 -n ns-login
  • Changer l'image d'un déploiement : kubectl set image deployment/<nom> <conteneur>=<image:tag> -n ns-login
  • Annuler une mise à jour (Rollback) : kubectl rollout undo deployment/<nom> --to-revision=1 -n ns-login
  • Tester en local sans IP publique : kubectl port-forward svc/<nom-svc> 9999:80 -n ns-login
📄 Squelette Standard YAML à Reconnaître

Les 4 blocs obligatoires : apiVersion, kind, metadata, spec. 

apiVersion: apps/v1          # v1 pour Pod/Service/Namespace, apps/v1 pour Deploy/RS
kind: Deployment             # Type de l'objet
metadata:
  name: dep-app              # Nom de la ressource
  namespace: ns-llaula       # Espace d'isolation
  labels:
    app: web
spec:
  replicas: 3                # Nombre souhaité
  selector:
    matchLabels:
      app: web               # Cible les pods avec ce label
  template:                  # Modèle pour fabriquer les pods
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: mon-conteneur
        image: nginx:1.16.1
        ports:
        - containerPort: 80
