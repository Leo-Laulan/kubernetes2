Module de Rectification des Lacunes

Chaque erreur commise est isolee ici. Une question est automatiquement retiree du bac des qu'elle est validee sans faute.

1. Architecture & Configuration CLI

  • Fichiers kubeconfig : kubectl recherche $HOME/.kube/config, ou la variable $KUBECONFIG, ou l'argument --kubeconfig.
  • Diagnostic cluster : kubectl cluster-info valide le Control Plane et CoreDNS. kubectl cluster-info dump extrait les logs de debogage profonds.
  • Namespaces : Objet de portee logique (kind: Namespace, apiVersion: v1). Filtrer les pods sur tous les namespaces exige -A ou --all-namespaces (la syntaxe -ALL ou -n all est invalide).

2. Pods : Unites Atomiques de Calcul

  • Definition : La plus petite unite deployable et ordonnancable de Kubernetes.
  • Multi-conteneurs : Partagent le meme Network Namespace (adresse IP unique, loopback localhost commun, obligation de ports distincts) et volumes de stockage declares.
  • Cycle de vie : Pending (en attente de scheduling ou de telechargement d'image) → Running (au moins un conteneur tourne) → Succeeded (arret normal code 0) ou Failed (arret avec code erreur).
  • Commandes d'inspection :
    • Structure brute : kubectl get pod <nom> -o yaml ou -o json
    • Extraction JSONPath : kubectl get pod <nom> -o jsonpath='{.spec.containers[*].name}'
    • Evenements et statut detaille : kubectl describe pod <nom> -n <ns>
    • Execution directe sans shell : kubectl exec -it <nom> -n <ns> -- <cmd>

3. ReplicaSets : Reconciliation Declarative

  • Objectif : Garantir qu'un nombre defini de pods identiques tourne a tout instant.
  • Decouplage par Labels : Le ReplicaSet ne verifie pas le createur du pod. Il gere tout pod portant les labels decrits dans spec.selector.matchLabels.
  • Gestion des ecarts :
    • Pod supprime manuellement : Detecte l'ecart (ex: 2 au lieu de 3) et instancie un pod de substitution (Pending → ContainerCreating → Running).
    • Pod cree manuellement avec labels identiques : Le total passe a 4. Le ReplicaSet detecte l'excedent et termine un pod (Terminating).
  • Ajustement a chaud : kubectl scale rs <nom> --replicas=N -n <ns>.

4. Deployments : Gestion du Cycle de Vie

  • Hierarchie : Deployment → supervise des ReplicaSets (nommes <deploy-name>-<hash-template>) → supervisent les Pods.
  • Mise a jour d'image : kubectl set image deployment/<nom> <conteneur>=<image:tag> -n <ns>.
  • Securite du RollingUpdate : Si une image erronee est declaree (ex: tag inexistant), le nouveau ReplicaSet echoue (ImagePullBackOff), mais l'ancien ReplicaSet maintient ses pods actifs : zero coupure de service.
  • Suivi et Rollback :
    • Statut d'avancement : kubectl rollout status deployment/<nom> -n <ns>
    • Historique des versions : kubectl rollout history deployment/<nom> -n <ns>
    • Retour arriere cible : kubectl rollout undo deployment/<nom> --to-revision=N -n <ns>
